Smartmind · live release

Smartmind Go-Live Guide

Put the finished site (security hardening, community blog, SEO fixes) onto your existing Vercel site and your existing Supabase project. No post, comment, member or image is deleted. Do the steps in order. Plan for about two hours the first time.

Your two values

Every command and SQL block below fills these in for you. Change them here if they are different.

The address must start with https:// and have no slash at the end. Use the same form (with or without www) in Supabase and in Vercel. The project reference is the repository's linked project (supabase/.temp/linked-project.json, name “smartmind”). Confirm it: it is the part after /project/ in the Supabase dashboard address bar for the project your live site uses.

Four rules for the whole guide
  • Never paste hosted-clean-install.sql into the live project. It deletes every login and all data.
  • Never run supabase db reset, and never run supabase db push on the live project unless a step says so.
  • Never put the service-role key in Vercel, in a file or in this page. It lives only in your own terminal, only for the admin step.
  • Each SQL block below runs inside begin; … commit;. If it shows an error, nothing was applied. Stop, copy the error text and send it to me. Do not retry blindly.
Always use the Copy button

Do not select text by hand, and do not copy from a PDF, a chat window or an older guide. The earlier rollout file broke because a hidden-character pattern in it was corrupted when copied. The SQL in this page contains only plain keyboard characters (checked when the page was built).

15 min

STEP 9

Supabase settings

20 min

The repository’s config.toml only configures the local stack. The live project has its own copy of each setting below, so set each once in the dashboard. Menu names move around; pick the closest match.

Address and sign-up

Where: Authentication → URL Configuration, and Authentication → Sign In / Providers (Email).

The two email templates

Where: Authentication → Emails (or Email Templates) → Confirm signup, then Reset password. Paste the whole block into the message body and set the subject line shown.

Keep the two links exactly as they are

They use {{ .SiteURL }} and {{ .TokenHash }}. Never replace them with Supabase’s ready-made {{ .ConfirmationURL }}. That link makes Supabase use up the one-time token before the site sees it, and people land on “That link has expired or was already used”.

Confirm signup, subject Confirm your Smartmind account:

Reset password, subject Reset your Smartmind password:

Email sending (Brevo)

Supabase’s built-in sender allows only a few emails an hour, which is too few for real sign-ups. Brevo has a free plan; check its pricing page for the current daily limit.

  1. At brevo.com create an account, then Senders, domains & dedicated IPs → Senders → Add a sender. Use an address that belongs to the team and enter the code Brevo emails to it.
  2. Strongly recommended: Domains → Add a domain and add the DKIM and DMARC records Brevo shows to your domain’s DNS. A free @gmail.com address as the sender is often refused or goes to spam.
  3. In Brevo: SMTP & API → SMTP, press Generate a new SMTP key and copy it at once (it is shown once).

Why the address matters

The live site had been publishing http://localhost:3000 in its canonical links, sitemap.xml, robots.txt and share images, so Google had no reason to index your real address. A live build now refuses to finish when the address is missing, is localhost or is not https.

STEP 11

Deploy the code

15 min
Pushing to master goes live

Vercel deploys master to production by itself. Do this only after steps 1 to 10 are finished and checked. The database is safe for both the old and the new code, so there is no gap.

11a. Merge on your computer

Where: Windows PowerShell, in the project folder.

Expected: a clean merge with no conflicts.

11b. Check the merged code

Start Docker Desktop first and run npx supabase start; some tests and the build use the local database. Close any running npm run dev window first. The merge changes no packages, so no install is needed. These are the same checks that passed on a copy of this exact merge.

Done whentypecheck prints no errors, the tests end with all passed, and the build ends with the route table and no error.

11c. Publish

Watch Vercel → Deployments until the new one says Ready. If the build fails, the message says what is missing (most often NEXT_PUBLIC_SITE_URL); fix the variable and press Redeploy. A failed build never replaces the working site.

Want a review gate first?

Instead of merging on your computer, push the branch (git push -u origin audit/auth-hardening), open a pull request on GitHub and merge it there. The result is the same deployment. A preview deployment is good for looking at the layout only: it does not run the address check and has no database settings unless you add them for the Preview environment.

APPENDIX A

If something goes wrong

What you seeCause and fix
“syntax error”, or odd characters in pasted SQLThe text was copied by hand or from another place. Use the Copy button on this page and paste into a new query.
“relation … already exists” when adding the community tablesThey are already there. Nothing changed. Go on to step 4.
“must be owner of table objects”Step 6 fallback: do the media policies in the Storage dashboard.
“Email rate limit exceeded” when registeringSupabase’s built-in sender is still in use. Finish the Brevo SMTP settings and raise Emails sent per hour.
Every emailed link says “expired or already used”The templates use {{ .ConfirmationURL }}, or the Site URL is wrong. Paste the two templates from step 9 again and recheck the Site URL.
Vercel build fails with NEXT_PUBLIC_SITE_URLThe variable is missing, points at localhost, or does not start with https://. Fix it for Production and press Redeploy.
Images are broken after step 6The bucket was not public. Run the step 14 rollback (it restores media: public read), then check Storage → media is Public.
A member’s name became “Member”Their old name contained a reserved word (admin, smartmind, moderator, former member). Set a plain name with the rename block in step 4. It is accepted when it has no reserved word.
The admin cannot log inRun the admin command in step 12b against the live project. An existing admin’s password is reset without any extra flag.

For anything else: stop, copy the exact message, note the step number, and send both to me.

APPENDIX B

If the live project is empty

Use this only if step 1 showed the project has no site tables or no content. Never on a project that holds content you want to keep.

  1. Paste hosted-clean-install.sql (project folder root) into the SQL Editor and run it. It rebuilds everything up to the community migrations and creates the media bucket.
  2. Apply steps 4 to 7 of this guide (the pre-flight will report there are no members yet).
  3. Bring the content from your local database (posts, team, publications, awards, partners, projects and the image files). The hosted tables must be empty; the script refuses to run otherwise and never overwrites anything. It does not copy logins or blog posts and comments.
